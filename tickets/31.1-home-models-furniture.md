# 31.1 — Home models: room and furniture

Subticket of [31 — Story intro](31-story-intro.md). Goal: the room shell and the furniture that frames the panels exist as meshed SDF models in `content/models/home/`, with home materials.

Steps:
1. Read the scout's bounds (`content/models/characters/amanita-scout.sdf`) and an existing model with parts and materials (e.g.
   `content/models/machines/`, `content/models/games/`) for the file style, and `content/parts` / the materials folder for how
   materials are declared.
2. Add the `materials/home/` family: wood, plastic, fabric, wallpaper (warm, low-contrast stripes in the material, not the mesh), gold
   (reuse the existing gold/brass if one fits), crisp, can; toon setup, subsurface meaningful where the ticket says so.
3. Model, in `content/models/home/`: `room-shell` (4 x 3 m floor, three walls 2.2 m high, skirting), `window` (frame, sill, half-drawn
   curtains) and `window-backdrop` (a flat quad card for the dusk sky), `desk` (1.2 x 0.6 m, 0.55 m high, one drawer), `chair` (gaming
   chair, 0.5 m seat height, the seat a separate `Seat` part), `monitor` (0.8 m wide, chunky bezel, stand, a `Screen` part that is a
   flat quad with UVs), `keyboard`, `mouse` and `mousepad`.
4. Mesh them at 256 (`sdf unity --resolution 256 --lods 3` or `sdf mesh`), check part names and scale against the scout, and add a
   pipeline test that every `home/` model parses, builds and has the parts named above (follow `SDFPipeline.Tests/Models/*Tests.cs`).

Check: `dotnet build` and `dotnet test` pass; the models mesh. Acceptance: furniture reads as made for a 1 m mushroom (state the
measured sizes in the report). Dependencies: none.

Common rules (every subticket of 31): read `tickets/31-story-intro.md` (the whole ticket) and `tickets/README.md` first. Work only in this
worktree, never the main checkout. Meshing always at 256 cells, 3 LODs (home models: LOD0 is enough), never 512. Each SDF pointer id is
one node (reuse only via variables). One theme per scene; toon look only; nothing in the runtime may need compute shaders (WebGL2);
HUD/GUI elements about 5 px from the screen edges. 42 is always "they", Prime is "he". Generated files are not in git. Match the
surrounding code style and comment density. Do not commit; the lead commits. Any agent you spawn must be a Sonnet agent
(`model: "sonnet"`) and must be told the same. Report: files changed, commands run, test results (failures stated honestly), what is left
for a human look.
