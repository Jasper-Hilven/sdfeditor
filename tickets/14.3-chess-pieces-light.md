# 14.3 — Chess pieces, light, and the plain piece materials

Goal: the 10 light chess models become classic turned Staunton-style pieces with no mushroom features.

Files: `content/models/chess/*-light*.sdf` (pawn, rook, knight, bishop, queen, king; standing and fallen as in the directory). Create
plain materials `chess_light.sdfmat` and `chess_dark.sdfmat` next to the existing `chess_{light,dark}_{cap,stem,gills}.sdfmat` (find them
with `find content -name "chess_*"`; follow their format; a felt base material is optional). Do NOT delete the old cap/stem/gills
materials yet (14.4 migrates the dark pieces first).

Shapes: base disc, collar, shaft, head; king's cross, queen's coronet, bishop's mitre with its slit, rook's battlements, knight's horse
head with a mane, pawn's ball. Keep size (height and footprint), pose, `Detail` and the `collider` line so the placements and the overlap
test from 12.6 still hold. Same toon style. Fallen variants are the same piece lying down.

Steps: edit each model; `sdf render` each changed model (the `.png` next to it) and LOOK at every image; iterate until each reads as its
chess piece. Mesh the changed models at 256 cells, 3 LODs (`sdf mesh content/models/chess --into Unity/Assets/Mushrooms/Generated/chess --resolution 256 --lods 3`;
mesh only if the CLI lets you; otherwise the full folder). LOD0 triangles per piece should be sane (13 had 4k-8k).

Check: no cap/stem/gill/bulb/wart/spore text in the light files; `dotnet build`, `dotnet test` (update tests naming old materials for light
pieces only). Dependencies: none (14.4 follows).

Common rules (every subticket of 14): read `tickets/14-chess-cube.md` and `tickets/README.md` first. Work only in this worktree, never
the main checkout. Meshing always at 256 cells, 3 LODs, never 512. Each SDF pointer id is one node. One theme per scene: board games, no
mushrooms, eyes or hands. Generated files are not in git. Do not commit; the lead commits. Any agent you spawn must be a Sonnet agent
(`model: "sonnet"`) and must be told the same. Report: files changed, commands run, test results (failures stated honestly), what is left
for a human look.
