# 14.8 — Re-mesh, rebake, rebuild, snapshots

Goal: everything regenerated and verified.

Steps: (1) grep the models, parts and materials the chessboard uses for leftover mushroom, eye or hand features; remove materials nothing
uses; (2) `sdf unity --resolution 256 --lods 3` (the `Update to Unity (256)` config) to remesh everything and rebake the chessboard level;
(3) copy Library from the main checkout, Unity batch `LevelBuilder.BuildAllInBatch` (see 14.2 for the command), logs clean;
(4) snapshots: eye height in the middle of the board, at a corner looking along a wall, looking up at the ceiling, a crowd close-up: LOOK
at each; note the triangle and draw-call counts the build prints (no budget work); (5) `dotnet build`, `dotnet test`. Fix small problems;
report big ones. Dependencies: 14.1-14.7.

Common rules (every subticket of 14): read `tickets/14-chess-cube.md` and `tickets/README.md` first. Work only in this worktree, never
the main checkout. Meshing always at 256 cells, 3 LODs, never 512. Only one Unity instance per project path. One theme per scene: board
games, no mushrooms, eyes or hands. Generated files are not in git. Do not commit; the lead commits. Any agent you spawn must be a Sonnet
agent (`model: "sonnet"`) and must be told the same. Report: files changed, commands run, test results (failures stated honestly), what is
left for a human look.
