# 27.2 — Machine sets per level (generic)

Goal: a level chooses which machine models its turrets, tanks and helicopters use, and a room level gives helicopters their limits. Today the builder
makes `turret-<team>` and friends from `content/models/machines/` for every level. Tickets 28-30 reuse this.

Steps:
1. Find every place that names the machine models/prefabs (`grep -rn "turret-\|tank-\|helicopter-" Unity/Assets SDFPipeline`: builders, `Machines.cs`,
   `Unity/Assets/Battle/Runtime/*Machine.cs`, the unity mesh and prefab builders, tests). Add a level-file line `machines set=<name>` (default
   `mushroom` = today's models, so the meadow, fungal level and chessboard are unchanged) naming the set. Generic rule: the models/prefabs of a set other
   than the default are `<kind>-<set>-<team>` (`turret-toy-red`, parts `turret-toy-red-foot` …), kinds `turret`, `tank`, `helicopter`. Bake the set name
   into the level data; the `BattleSide`/`Machines` runtime reads it.
2. The machine prefab builder makes the prefabs for every set whose models exist; a missing set is skipped with a log line, not an error.
3. Helicopter limits in a room (`HelicopterMachine`, `MachineMotion`/`MachineRules` in `SdfBattle.Core`): when the level has a room, helicopters fly at
   6-12 m, at 16 m over bases, under a flight ceiling that is a level number (`machines set=toy ceiling=20`; default for a room `min(20, room height − 8)`),
   and keep 3 m off the walls instead of off the hills. Pure rules in Core with EditMode tests.
4. Tests: parse and bake of the new line, the default unchanged, the set reaching the prefab names, the helicopter limits.

Check: `dotnet test` and the SdfBattle EditMode tests pass. Acceptance: the three existing levels behave identically; a level can name `set=toy`.
Dependencies: none (27.8 supplies the models).
