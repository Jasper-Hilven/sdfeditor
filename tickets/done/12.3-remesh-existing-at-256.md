# 12.3 — Re-mesh the ten existing models at 256

Part of [12](12-game-pieces.md). Ten models were meshed at 512; the set must be consistent at 256 (the project's meshing rule).

## Goal

The ten `.glb` files already in `Unity/Assets/Mushrooms/Generated/games/` replaced by 256-cell versions with 3 LODs.

## Files

- Models in `content/models/games/` (`.sdf`): `card-ace-held`, `die-amanita`, `die-d8-webcap`, `die-porcini`, `domino-2-6-side`,
  `domino-5-5-standing`, `domino-6-3-lying`, `domino-chain`, `meeple-fallen`, `meeple-standing`.
- Parts: `die_pips`, `domino_*`, `meeple`, `card_ace`.
- Output: the same names in `Unity/Assets/Mushrooms/Generated/games/` (overwritten).
- This ticket file: fill in the "Result" section.

## Commands

```
dotnet build SDFPipeline.Cli -c Release
for m in card-ace-held die-amanita die-d8-webcap die-porcini domino-2-6-side domino-5-5-standing domino-6-3-lying domino-chain meeple-fallen meeple-standing; do
  /usr/bin/time -p SDFPipeline.Cli/bin/Release/net10.0/sdf mesh content/models/games/$m.sdf \
    Unity/Assets/Mushrooms/Generated/games/$m.glb --resolution 256 --lods 3 2>&1 | tee <scratchpad>/$m.log
done
```

One after the other, 10 minute timeout each (background and wait). Do not touch other models' `.glb` files.

## Acceptance

- All ten files rewritten (clearly smaller than before: `git diff --stat`), 3 LODs.
- Result section: per model the seconds, triangles per LOD, every log warning verbatim; for `die-amanita` the triangles of the
  separate `die_pips` mesh (843k to 22k at 512).
- If `domino-chain` or `card-ace-held` takes over 5 minutes, name the slow phase.
- `dotnet build` and `dotnet test` pass.

## Depends on

Nothing. Independent of 12.1 and 12.2.

## Result

All ten models re-meshed one after the other with `sdf mesh ... --resolution 256 --lods 3` (Release build), none touched the
`_512.glb` files or other models. Every model took 2 to 6 seconds, so nothing was slow: the longest is `card-ace-held` at 6.1 s (card
2.5 s plus 2 s for its LOD1), then `domino-chain` at 4.8 s (three dominoes, 3.6 s for the biggest). The files are 0.4-2.1 MB each
(for example `card-ace-held` 4.2 MB to 2.1 MB, `domino-6-3-lying` 0.87 MB to 0.41 MB); they are git-ignored, so `git diff --stat`
shows nothing. `dotnet build` and `dotnet test` pass (533 + 351 tests).

Odd things:

- `die-amanita` has no separate `die_pips` mesh. The model keeps the pips inside the die's own mesh (the `SmoothUnion` inside an
  intersection with a box, see the comment in the .sdf), so the body is one mesh of 6,598 triangles with the filleted pips; the
  843k to 22k separate pips mesh of the 512 run no longer exists. The same holds for `die-porcini` and `die-d8-webcap` (one body
  mesh each).
- Warnings, verbatim, both with the same cause (the eyes sit either side of a SymmetryX mirror, so they are meshed in place as one
  mesh instead of two instances):
  - `content/models/games/meeple-fallen.sdf: Part 'eye' is used 2 times but meshed in place, all uses as one mesh: a use is across the mirror of a SymmetryX`
  - `content/models/games/meeple-standing.sdf: Part 'eye' is used 2 times but meshed in place, all uses as one mesh: a use is across the mirror of a SymmetryX`
- No other warnings. `card-ace-held` correctly shows eye and hand as 2 instances each.
