# 30.1 — Emission: glow as a generic toon-shader feature

Goal: a material can glow. `emission` (0..1 amount, default 0) in `.sdfmat`, carried per vertex, added in `SdfToon` and `SdfToonFar` after the toon bands so a lit face keeps its colour in shadow; the outline pass unchanged. A strict no-op for every existing material (existing level.json, meshes and shaders render identically). Ground regions get the same (`emission` on a region material, e.g. `ground_trace`). Tickets 30.2-30.9 and 33 use it; 28/29 may too, so keep it generic.

Steps:
1. Find how material parameters reach the vertex data (every stream uv0-uv7 is used; uv5 is a float2). Make room for one scalar (widen or pack, the least invasive way; document the layout where the streams are documented). Pipeline: `.sdfmat` parse, mesh export (`sdf mesh`, GLB/Unity import path), ground chunk mesher (`GroundMesher`/`GroundRegions`), instance/prefab path.
2. Unity: `SdfToon`, `SdfToonFar` (and the ground shader if separate) read it and add `emission * baseColour` (unlit, un-banded) after lighting. Keep WebGL2-safe (check the interpolator count).
3. Tests: parse/default, vertex data round trip, existing meshes unchanged where practical, ground region emission. If Unity is runnable: batch compile of the shaders with no shader errors (first `cp -cR /Users/jasperhilven/RiderProjects/SDFProject/Unity/Library <worktree>/Unity/Library` if the worktree has none; see `tickets/done/14.2-chess-cube-unity-room.md` for the batch command). A WebGL2 compile check if feasible, otherwise say so.

## Status

Done (not committed).

- `emission` (0..1, default 0) is a `MaterialDefinition` parameter (last in `Parameters`), so `.sdfmat` parses it and `Mix` weights it like the others.
  `MaterialDefinition.Listed` leaves it out of `.sdfmat` writes, GLB material extras and level.json parameters while it is 0, so non-glowing
  materials and bakes are byte-identical to before.
- Vertex data: UV5 was a float2 (speckleDensity, speckleSize); it is now a float3 with `z = emission`, but only on meshes where some vertex
  glows (GLB attribute `_EMISSION`, written only then; `MushroomBuilder.Fill` widens TexCoord5 to 3 only then). Other meshes keep the float2
  stream, and the shaders read z as 0. No new interpolator (SdfToon: TEXCOORD8 stays one slot). No `BuilderVersion` bump (existing
  prefabs do not change; emissive models are new). Layout documented in SdfSurface.hlsl.
- Shaders: `SdfToonEmit` (SdfToon.hlsl) adds `albedo * emission` after `SdfToonShade` (bands, highlight, rim, sky tone), flat; used by
  `SdfToon.shader` and `SdfToonFar.shader`. Outline pass untouched.
- Ground: no vertex data there; a region's emission goes in the alpha of `_Region<i>Base` (grass: `_GroundBaseColor.a`), set by `LevelBuilder.GroundMaterial`
  from level.json; `SdfGround.shader` adds `sum(weight * emission * layerColour)` after the bands.
- Not done: the IDE's raymarched preview (`sdf-renderer.js`, `Webgl2CodeGenerator`) does not draw emission; it only matters for the toon mesh path.
- Tests: `SDFPipeline.Tests/Materials/EmissionTests.cs` (default/parse/round trip/omitted at 0, Mix, GLB attribute only on glowing meshes,
  ground region emission in the level bake). `dotnet build` clean, `dotnet test`: 533 + 745 passed, 0 failed.
- Unity: copied Library, `Unity -batchmode -quit` on the worktree project: no `error CS`, no shader import errors, exit 0. That only
  imports the shaders; variants (instancing, LOD fade, scatter, WebGL2 target) were not compiled, and no WebGL2 compile check was made.
- Human look: make a model with a material with `emission = 1`, mesh it (`sdf mesh`, `sdf unity`) and see it glow flat in shadow; a ground
