# 15.1 — `castle1` parts and model, materials, render

Part of [15](15-meadow-without-fungi.md). Read that ticket's "`castle1`: the stone castle" section, [`06.0-rules.md`](06.0-rules.md)
and [`09-castle-fixes.md`](09-castle-fixes.md) first. Depends on: nothing.

## Work

- Parts in `content/parts/castle_stone/`: `stone_wall_bay`, `stone_wall_gate`, `stone_wall_joint`, `stone_tower_large`,
  `stone_tower_small`, `stone_gate_turret`, `stone_keep`, `stone_stair`, `stone_merlon`, plus details `stone_window_frame` and
  `stone_lantern` (stone / iron). Each mirrors its `content/parts/castle/castle_*` counterpart: same footprint, same walk heights
  (5 m, 5.15 m, 5.3 m), same 15 cm steps between overlapping floors, same origin and `Part` interface. Forms: straight walls with a
  batter at the foot, round towers with conical roofs, square merlons, a square keep, stone steps along the keep.
- Model `content/models/buildings/castle1.sdf`, laid out exactly like `castle0.sdf` (same bay positions, joints, towers, keep, gate,
  stairs, detail placements where a stone variant exists). No mycelium, young amanitas, veil or wall shelves.
- Materials: `castle_stone.sdfmat` gets `pattern stones size=0.55 grout=0.035` and a rewritten comment; `castle_roof.sdfmat` comment
  rewritten; new `materials/buildings/castle_wood.sdfmat` for the gate. No `amanita_*` material anywhere in castle1.
- Every repeated part is a `Part` use (rigid placements only), so each is meshed once.
- Do NOT change any file in `content/parts/castle/`, `castle0.sdf`, or the `castle_wall`/`castle_stem`/`castle_shelf` materials. Each
  pointer id is one node; reuse only via variables.
- `sdf render` a PNG of `castle1` next to the model, as `castle0` has.
- Check the model loads (`dotnet build`, CLI). Meshing is 15.2.

## Done when

All files above exist, `castle1.sdf` renders a stone castle that is `castle0`'s twin in layout, `dotnet build` and `dotnet test`
pass, and the work is committed.
