# 27.9 — The level file `toybox.level` and its tests

Goal: `content/levels/toybox.level` fills every section of 27 with the real models (all exist after 27.4-27.8; the room, machine-set and mover formats after
27.1-27.3) and the tests accept it.

Steps:
1. Write the file in the commenting style of `content/levels/chessboard.level` and `fungal.level`: header with the 60x scale and the theme; `play size=(150, 100) noise=0`;
   `room size=(150, 64, 100) walls=toybox-wall ceiling=toybox-lid` with the lid-crack strip and the light data; `regions base=felt` with `playmat`, `road`, `foam`
   (`wobble=0`); `machines set=toys` with its ceiling; the two `sides` (castle `toy-castle0` at (−62, 0) yaw 90 and (62, 0) yaw −90, `flatten=22`, no ground paving,
   flag stand, spawn, pods per 27's tables, four turrets and a machine zone per side); the two neutral pods; the hand-placed landmarks (each group starting with a
   comment line), the 12 track curves and 2 bridges; the `mover` for the train; the scatter and trees sections (`reach=0`, bands, margins as in 27); `draw` groups for
   bits, toys, castle and landmarks; the pennants placed with `y=`. Write the ground materials `ground_felt`, `ground_playmat`, `ground_road`, `ground_foam` in
   `materials/ground/` (felt fibre pattern, cream rug, grey road with centre dashes, pale yellow foam with 4 m tile seams from the world grid like `ground_tiles`).
2. Tests: `toybox` in `BattleSidesTests.LevelNames` with its weapons (pistol, blob-gun, sniper, flamethrower); `ContentToyBox_HasOnlyToys` (every model named is from
   `toys/`, the pickups, weapons, battle objects or the `toy` team machines; no material from another theme's folder: none from `chess/`, `games/`, `grass/`,
   `fungi/`, `trees/`, …); `LevelFileTests` and the scatter tests pass. Mirror, clearances and lanes as `BattleSidesTests` checks them.
3. Bake it (`sdf level content/levels/toybox.level --into Unity/Assets/Level/Generated/toybox`) and report instance counts and baked sizes. When a clearance test
   fails, change numbers in the file (not the tests), keeping 27's intent, and say so in your report.

Check: `dotnet build`, `dotnet test`. Acceptance: the bake succeeds, all tests pass, the layout mirrors across x = 0. Dependencies: 27.1-27.8.

Common rules (every subticket of 27): read `tickets/27-toy-box-level.md`, `tickets/README.md` and `tickets/done/26-level-ruleset.md` first. Work only in this
worktree (the absolute path the lead gives you), never the main checkout. Meshing always at 256 cells, 3 LODs (castle parts 128), never 512. Each SDF pointer
id is one node (reuse only via variables). One theme per scene: toys; no mushroom features on props. Toon look only, no live raymarching, nothing that needs
compute shaders (WebGL2). Team colours stay out of props: no red or blue toy groups (check each png). Generated files (glbs, mesh assets, level bakes) are not
in git. Match surrounding code style and comment density. Do not commit; the lead commits. Do not spawn agents. 27's open questions are answered with its
defaults: the train pushes and does 20 damage, riding is in, the machines keep the scouts' floating eyes, the teddy and jester have painted toy faces. Report:
files changed, commands run, test results (failures stated honestly), what is left for a human look.
