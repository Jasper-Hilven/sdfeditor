# 31.3 — Home placement and HomeBuilder

Subticket of [31 — Story intro](31-story-intro.md). Goal: `Home.unity` is built by code from a text placement file and the meshed home models; it is editor-only; no battle level can use a
home model.

Steps:
1. Decide the placement format: the level format's `place` lines if a level can do without ground (as the chess cube's room does),
   otherwise `content/scenes/home.txt`. Put 42's room in it: room shell, window and backdrop, rug, desk with monitor, keyboard, mouse,
   mousepad, snack bowl, crisp bag, soda can, chair, shelf with trophy and shelf-stuff, lamp, poster. Coordinates in the room's own frame
   (floor at y=0, camera corner at the open fourth wall).
2. Add `HomeBuilder` (Unity editor, in `Unity/Assets/Story/Editor/`, like `LevelBuilder` / `GuiScreens`): menu Tools > SDF Story > Build
   Home, a batchmode `-executeMethod` entry, builds `Assets/Scenes/Home.unity` from the placement and the meshed prefabs, adds the
   warm lamp light and a cool monitor light, a placeholder dusk ambient, and two scout actors (`amanita-scout` as "42" on the chair, a
   second for Mushroom 7 parked off stage) plus four chanterelle `hand` actors parked off stage, all named so 31.4 can find them. Home
   is NOT added to the build settings' scene list. Keep Editor code out of the build with the asmdef layout the other folders use.
3. Add a pipeline test (`SDFPipeline.Tests`) that no `content/levels/*.level` file places a model under `home/`, and that the home
   placement references only `home/` models plus the scout characters.
4. Home models stay out of level bakes: check `sdf unity` / `sdf level` do not require them to be placed anywhere.

Check: `dotnet test` passes; if Unity is runnable, build Home in batchmode without errors, otherwise say so. Dependencies: 31.1, 31.2.

Common rules (every subticket of 31): read `tickets/31-story-intro.md` (the whole ticket) and `tickets/README.md` first. Work only in this
worktree, never the main checkout. Meshing always at 256 cells, 3 LODs (home models: LOD0 is enough), never 512. Each SDF pointer id is
one node (reuse only via variables). One theme per scene; toon look only; nothing in the runtime may need compute shaders (WebGL2);
HUD/GUI elements about 5 px from the screen edges. 42 is always "they", Prime is "he". Generated files are not in git. Match the
surrounding code style and comment density. Do not commit; the lead commits. Any agent you spawn must be a Sonnet agent
(`model: "sonnet"`) and must be told the same. Report: files changed, commands run, test results (failures stated honestly), what is left
for a human look.
