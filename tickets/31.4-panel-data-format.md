# 31.4 — Panel data format and the twelve panels

Subticket of [31 — Story intro](31-story-intro.md). Goal: the intro is data: a text file with the twelve panels, parsed by a pure C# reader with tests.

Steps:
1. Design `content/story/intro.txt` (line based like the level files, comments with `#`): per panel `panel N stage=home|warp|meadow`,
   `camera pos= rot= fov=`, `actor <name> pos= rot= scale=` for the scouts' body, eyes and hands, prop part poses (chair `Seat`, crisps,
   snack bowl), `screen texture=screen-meadow|screen-victory|screen-glitch|screen-prime glitch= bulge=`, `lamp intensity=`,
   `frame x= y= w= h=` (inset frames), devices (`speedlines radial|parallel`, `motionlines`, `burst`), and text (`balloon speaker= text=
   anchor= tail=`, `caption text=`, `sfx text=`, a jagged sky box for Prime). Write the reader in `SDFPipeline/` (e.g.
   `SDFPipeline/Story/StoryFile.cs`) and have Unity use the same parsing through the existing mechanism the level format uses (check how
   Unity reads `LevelFile`; if it links or copies the source, do the same).
2. Fill all twelve panels from the ticket's table (picture and text). Speakers: `42` (they), `Prime` (he), `Mushroom 7`, narrator.
   Text exactly as in the ticket table. At most 2 balloons per frame, each under about 12 words.
3. Unit tests: parse the real file; exactly 12 panels numbered 1..12; every panel has a stage and camera; each frame has at most 2
   balloons; every balloon has a known speaker and a tail target; every `screen` texture is one of the known four; error cases for
   malformed lines.

Check: `dotnet build` and `dotnet test` pass. Dependencies: 31.3 (actor and part names).
