# 31.5 — Capture core and the comic post pass

Subticket of [31 — Story intro](31-story-intro.md). Goal: an editor tool that renders a panel's 3D stage with the heavy comic look, no lettering yet.

Steps:
1. `StoryCapture` (Unity editor, `Unity/Assets/Story/Editor/`): Tools > SDF Story > Render Panels and a batchmode `-executeMethod`, as
   `GuiSnapshot`; an optional panel number renders only that one. Reads `content/story/intro.txt` (31.4), opens the stage (`Home.unity`;
   `Meadow.unity` for arrival panels with nothing added but the scouts; the warp stage comes in 31.7), poses the camera, actors and
   props, renders at 3840 x 2160 and downsamples to 1920 x 1080 into `Assets/Story/Panels/panel-NN.png` (no mipmaps, compressed for the
   web by the importer settings the script applies; the whole set about 6 MB or less).
2. Heavier toon at capture time only: a capture-only global (shader keyword or global property) that gives 2-3 hard bands, a stronger
   rim and about 2x outline width on `SdfToon` / `SdfToonOutline`, with no change to the look in game when it is off. Check the shaders
   still build for WebGL2.
3. Post pass shader and script in `Assets/Story/Editor/` (editor only, never ships): wobbly ink line from depth and normal edges,
   halftone dots on a 45 degree grid (about 6 px at 1080p) filling the shadow band in a darker shade of the surface colour (get the band
   from a second camera pass writing the band index, not from colour guessing), warm paper grain and slight posterisation.
4. Screen material (editor only): unlit, texture, scanlines, glitch amount (block offset, blue tint, tear), soap-film bulge as a vertex
   offset by a uniform. Used by the monitor's `Screen` part.

Check: Unity compiles (batchmode `-quit` reports no errors) and panel 1 renders to a PNG you can look at; say honestly if Unity could not
run. Dependencies: 31.3, 31.4.

Common rules (every subticket of 31): read `tickets/31-story-intro.md` (the whole ticket) and `tickets/README.md` first. Work only in this
worktree, never the main checkout. Meshing always at 256 cells, 3 LODs (home models: LOD0 is enough), never 512. Each SDF pointer id is
one node (reuse only via variables). One theme per scene; toon look only; nothing in the runtime may need compute shaders (WebGL2);
HUD/GUI elements about 5 px from the screen edges. 42 is always "they", Prime is "he". Generated files are not in git. Match the
surrounding code style and comment density. Do not commit; the lead commits. Any agent you spawn must be a Sonnet agent
(`model: "sonnet"`) and must be told the same. Report: files changed, commands run, test results (failures stated honestly), what is left
for a human look.
