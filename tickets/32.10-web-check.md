### Audit (Campaign, GUI, Story, Battle code the campaign touches, Level runtime; all non-editor code under `Unity/Assets`)

- **Compute shaders**: none. No `.compute` file, no `ComputeShader`/`ComputeBuffer`/`GraphicsBuffer`/`StructuredBuffer`/geometry stage in any project shader (the toon, sky, spores, ground, room, effect, GUI shape and the two Battle/Resources shaders are `#pragma target 3.0/3.5`; the toon family states "WebGL 2 and up" in a comment). `StaticSunShadow` uses a `RenderTexture` + `CommandBuffer` (fine on WebGL2). TextMesh Pro's own shaders are stock.
- **`System.IO` / files**: no runtime write. `Level/Runtime/ScatterInstances` uses `BinaryReader` over a `MemoryStream` of a `TextAsset`'s bytes only. No `File`, `Directory`, `persistentDataPath`, `StreamingAssets`, `UnityWebRequest`.
- **PlayerPrefs**: the campaign save (`PlayerPrefsCampaignStorage.Set`) already calls `Save()`. **Finding**: `GuiSettings` (gore, sensitivity, volume, shake, FPS, hints) and the quality level wrote PlayerPrefs with no `Save()`, so a web tab closed after changing a setting lost it. **Fixed**: `GuiSettings.Save()` and `GuiSettingsMenu.OnDisable` (the settings screen's root is deactivated when it closes) calls it in play mode, so a slider drag writes once, not per step. Difficulty goes through the campaign save, which already saves.
- **`Application.Quit`**: only in `GuiFlow` (`GuiCommandId.Quit`, editor stops play mode instead); the only QUIT button is the title's, hidden by `GuiTitle` for `RuntimePlatform.WebGLPlayer`. Nothing else quits.
- **Threads / async**: none (`Thread`, `Task`, `async`, `Parallel`, `Process`, blocking waits). Loads are coroutines over `LoadSceneAsync`.
- **Editor-only code in runtime**: every `UnityEditor` use in non-editor folders is under `#if UNITY_EDITOR` (`GuiFlow`, `Machines.Load`, `Match` spectate preference, gizmo labels); `Machines` takes its prefabs from the scene's serialized fields in a player (Fungal has them; Meadow and Chessboard have no machines by design).
- **`Shader.Find`**: one, `Sprites/Default` in `WarmUpPlayer` (the gold arrow); it is in the Always Included Shaders list (id 10753), so it exists in a build. `Resources.Load` shaders are in `Resources` folders, so they ship.
- **Pointer lock**: locks happen only from a click or a button: Loading's CLICK TO PLAY (`SceneLoader`), the beat's/warm-up's CLICK TO PLAY (`BeatPlayer.Handed`), RETRY in place (button click), `FirstPersonController` (click on the view). Esc/lock loss while the HUD is up pauses (`GuiFlow.PauseOnLostLock`; `Keys()` runs first, so Esc plus a lost lock in one frame does not toggle back). RESUME (button or Esc) does not re-lock itself: the player clicks the view once (`FirstPersonController`), which is a gesture-safe way on the web.
- **Intro**: `StoryIntro` loads its prefab from `Resources` (12 panels JPG 1920x1080, `maxTextureSize` 2048, no mips, default compression for WebGL) only when it starts; music file `intro-music.ogg` is still missing (31's note), the code copes.
- **Build settings** (ProjectSettings): WebGL gzip + decompression fallback on, data caching on, memory initial 32 MB / max 2048 MB with geometric growth, exceptions on, threads off, input handler "both". Stripping `stripEngineCode: 1`; the save uses `JsonUtility` on `[Serializable]` classes (referenced by generic use, so kept), to be proved by the save test below.
