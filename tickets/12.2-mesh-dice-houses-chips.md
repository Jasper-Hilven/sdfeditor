# 12.2 — Mesh the tumbled die, Monopoly and poker chip models at 256

Part of [12](12-game-pieces.md).

## Goal

`.glb` files (3 LODs) for the six models of these families that are not meshed yet, with time, warnings and triangles recorded.

## Files

- Models in `content/models/games/`: `die-amanita-tumbled.sdf`, `monopoly-house.sdf`, `monopoly-house-toppled.sdf`,
  `monopoly-hotel.sdf`, `poker-chip-stack.sdf`, `poker-chip-rolling.sdf`.
- Parts they use: `content/parts/monopoly_house.sdf`, `porthole_window.sdf`, `die_pips.sdf`, `poker_chip_red.sdf`, `poker_chip_blue.sdf`.
- Output: `Unity/Assets/Mushrooms/Generated/games/<name>.glb` (and `.meta` files if the folder tracks them).
- This ticket file: fill in the "Result" section.

## Commands

```
dotnet build SDFPipeline.Cli -c Release
for m in die-amanita-tumbled monopoly-house monopoly-house-toppled monopoly-hotel poker-chip-stack poker-chip-rolling; do
  /usr/bin/time -p SDFPipeline.Cli/bin/Release/net10.0/sdf mesh content/models/games/$m.sdf \
    Unity/Assets/Mushrooms/Generated/games/$m.glb --resolution 256 --lods 3 2>&1 | tee <scratchpad>/$m.log
done
```

One after the other, a 10 minute timeout each (run in the background and wait).

## If a model is slow (over about 3 minutes)

Name the slow phase from the log; try a root `Detail detail=` below the current value, or fewer small primitives. Do not change the
mesher's code. Re-time after each change.

## Acceptance

- Six `.glb` files exist, non-empty, 3 LODs, meshed at 256.
- Result section: per model the seconds, triangles per LOD, and every log warning verbatim. In particular for `poker-chip-stack`,
  `monopoly-hotel` and `monopoly-house`: does the log say the parts `poker_chip_red`/`blue`, `porthole_window` and the eyes are
  meshed once and instanced, or "meshed in place" (and why)?
- `dotnet build` and `dotnet test` pass.

Nothing. Independent of 12.1 and 12.3.
